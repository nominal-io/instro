# instro docs: agent instructions

## About this project

- Open-source documentation for [`instro`](https://instro.nominal.io), a Python library for test equipment automation.
- Built on [Mintlify](https://mintlify.com). Pages are MDX files with YAML frontmatter.
- Configuration lives in `docs.json`.
- Run `mint dev` to preview locally. Run `mint broken-links` before opening a PR.
- Reusable text snippets live in `snippets/` (e.g. `snippets/glossary/channel.mdx`).

## Site structure

Routing is a strict 1:1 mapping of file path (relative to `docs.json`) to URL — no folder/index collapsing, no glob-based nav. A page not listed in `docs.json`'s `pages` arrays is still a real, reachable "hidden" page (linked to from elsewhere, just absent from the sidebar); most driver and protocol-variant pages are hidden this way.

| Path | Contents |
|---|---|
| `overview.mdx`, `quickstart.mdx`, `installation.mdx`, `cli.mdx`, `using-instro.mdx` | Overview tab. |
| `<category>.mdx` (`scope`, `psu`, `dmm`, `eload`, `daq`, `awg`, `flowcontroller`) | Instruments tab: one guide per category — intro, minimal constructor example, vendor card grid, example link, "Details" section. `instruments.mdx` is the tab's landing page. |
| `<category>/<Driver>.mdx` | One hidden page per vendor driver (e.g. `psu/BK9115.mdx`), linked from its category's card grid. Just two imports: the card snippet and the driver-page snippet. |
| `library/` | Conceptual/reference content: `library.mdx`, `publishers.mdx`, `exceptions.mdx`, `contrib.mdx`, `config-files.mdx` (shared JSON config field reference for every category), `custom-instruments.mdx` (all per-category "Driver Development" sections, one heading each, plus the "Custom Instrumentation" — build-a-new-type — walkthrough), `protocols/`, `transports/`. |
| `examples/` | One `index.mdx` per category, generated by `generate_examples.py`, linking to that category's individual (also generated, hidden) example pages. `unstable/index.mdx` and `contrib/index.mdx` are the exceptions: one page per workspace package, with a heading per submodule. `docs.json`'s Examples tab lists only the index pages — adding/removing an example script never touches `docs.json`. `just check-examples` (run in CI) fails on page drift or on an index page missing from the Examples tab. |
| `snippets/drivers/<category>/` | Reusable content — **never built as standalone pages**, even unimported (the one Mintlify folder exempt from becoming routes). `<category>.mdx` is the vendor card-grid aggregator imported by that category's guide page. `<category>/<slug>/` holds one driver's `card.mdx` (the vendor card, imported by both the aggregator and the driver's own page), `driver-page.mdx` (the driver page's body), and `image.png`. |
| `migration/`, `images/`, `logo/` | Migration guides, static assets. |

**Gotcha:** a page imported elsewhere as a component (`import X from "/path/to/page.mdx"`) stops being servable at its own route — 404s there, regardless of whether it's also `docs.json`-listed. `mint broken-links`/`mint validate` don't catch this; verify any `import .../*.mdx` outside `snippets/` with `mint dev` (hit the imported page's own URL) or a full `mint export`.
## Tasks 
### Adding a new instrument driver

For an existing category (`scope`, `psu`, `dmm`, `eload`, `daq`, `awg`, `flowcontroller`, `i2c`). Touches only files under `docs/guides/` — never `docs.json`:

1. `snippets/drivers/<category>/<slug>/image.png` — equipment photo.
2. `snippets/drivers/<category>/<slug>/card.mdx` — the `<Card>` linking to `/<category>/<DriverClassName>`.
3. `snippets/drivers/<category>/<slug>/driver-page.mdx` — intro line, a `## Creating an Instro<Category> with <Driver>` example, and a closing link to the driver's SDK reference page. Copy the shape of an existing driver in the same category.
4. `<category>/<DriverClassName>.mdx` — frontmatter, `import Card ...` + `import DriverPage ...`, then `<Card />` + `<DriverPage />`. Not listed in `docs.json`: a hidden page, reached only through its card.
5. Add the new component's import and `<Component />` to `snippets/drivers/<category>.mdx`'s `<Columns>` grid, so it shows up on the category guide's "Supported Vendors" section.
6. Point the driver page's SDK links at the driver's class page, `https://nominal-io.github.io/instro/instruments/generated/<dotted.path.to.DriverClass>/`. That page only exists once the driver is in the Vendor Drivers table and hidden autosummary list of `docs/sdk/instruments/<category>.md` (see [`docs/sdk/AGENTS.md`](https://github.com/nominal-io/instro/blob/main/docs/sdk/AGENTS.md#adding-a-vendor-driver)) — `docs/sdk` is a separate Sphinx site, not this one, but the link is dead without it. Verify with `just build-docs && just check-sdk-links`.
7. Run `mint broken-links`. If the driver page's imports touch anything that's also `docs.json`-listed, run a full `mint export` too (see the gotcha above).

### Adding a new instrument class

A whole new `InstroX` category. Touches `docs.json` and several shared pages, not just the category's own guide:

1. **Category guide page** — `<category>.mdx` at the guides root, matching the shape of the existing category pages: intro paragraph, minimal `## Creating an Instro<Category>` example, "## Supported Vendors" card grid, "## Example" link, "## Details", and a one-line "## Custom Driver Development" pointer at the end.
2. **Driver snippets** — `snippets/drivers/<category>.mdx` (the card-grid aggregator) plus one `snippets/drivers/<category>/<slug>/` folder per initial driver, and their hidden `<category>/<DriverClassName>.mdx` pages. See "Adding a new instrument driver" above for the shape of each.
3. **`docs.json`** — add `"<category>"` to the `Docs` tab's Instruments group `pages` array. This is the one case that needs a manual nav edit; individual drivers within an existing category never do.
4. **`instruments.mdx`** — add `import <Category> from "/snippets/drivers/<category>.mdx";` and a heading of the form `### <label>: InstroCategory` (the class name in inline code) followed by a `<Category />` block, positioned to match `docs.json`'s Instruments order.
5. **`library/custom-instruments.mdx`** — add a `## <Category display name>` section under "# Driver Development", positioned to match the Instruments TOC order (see Site structure above), and add it to the intro Tip's jump-link list.
6. **`library/config-files.mdx`** — if the category accepts `config=`, add a subsection for its state-block fields, matching the existing per-category subsections.
7. **Examples** — add script(s) under `examples/<category>/` (or the relevant `packages/instro-*/.../examples/`), run `just gen-examples` to generate the example pages and the category's `index.mdx`, then add one line to the "Contents" group of `docs.json`'s Examples tab pointing at that index — the one manual edit the generator can't make (`just check-examples` fails without it). Also add the folder's display name to `CATEGORY_TITLES` in `generate_examples.py` (otherwise it's title-cased from the folder name) and a card to `examples.mdx`, neither of which is checked. Unstable and contrib examples (`packages/instro-{unstable,contrib}/instro/{unstable,contrib}/<submodule>/examples/*.py`) are the exception: each package's examples land on a single `examples/{unstable,contrib}/index.mdx`, one heading per submodule, so a new submodule needs no `docs.json` edit.
8. **`docs/sdk/`** (sibling Sphinx site) — create `docs/sdk/instruments/<category>.md` in the category page layout from [`docs/sdk/AGENTS.md`](https://github.com/nominal-io/instro/blob/main/docs/sdk/AGENTS.md#category-page-layout) and add it to the Instruments toctree in `docs/sdk/index.md`, so step 6 of "Adding a new instrument driver" has somewhere to link.
9. Verify with `mint broken-links`, `mint validate`, and a full `mint export`.

## Terminology

- Refer to the library as **`instro`** (the package name). Reserve *Nominal* for the platform it integrates with (Nominal Core, Nominal Connect, the Nominal publishers).
- The instrument HALs are **`InstroScope`**, **`InstroPSU`**, **`InstroDMM`**, **`InstroDAQ`**, **`InstroAWG`**, **`InstroELoad`**, **`InstroFlowController`**, **`I2CInterface`**: keep the casing.
- A *channel* is a named signal for a series of measurements or computed values. The inline glossary tooltip is in `snippets/glossary/channel.mdx`.

## Style preferences

Follow Nominal's writing style guide. The rules that bite most often here:
- be concise and clear. 
- references to a class/module should be linked to the sdk as appropriate
- Active voice. Prefer the imperative over repeated *you* (*Configure the check*, not *You can configure the check*).
- No em-dashes or en-dashes. Use a period, colon, semicolon, comma, or parentheses.
- Refer to Nominal in the third person, never *we* or *our platform*. Reserve *we* for cases where Nominal is the actor (*Nominal recommends*).
- Lowercase data primitives (*channel*, *source*). Capitalize product names (*Nominal*, *Nominal Connect*, *Nominal Core*). Instrument HAL classes keep their code casing (`InstroPSU`).
- Keep sentences concise: one idea per sentence.
- Use sentence case for headings.
- Bold for UI elements: Click **Settings**.
- Code formatting for file names, commands, paths, identifiers, and code references.

## Content boundaries

- This repo documents `instro` only. Nominal Core, Nominal Connect, and the dashboard are documented elsewhere: link out, don't re-document.
