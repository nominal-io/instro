# Contribute to the instro documentation

Thank you for your interest in contributing! This guide covers how to add docs for a new driver or instrument class. 

For agents, use [AGENTS.md](./AGENTS.md).

## How to contribute

### Option 1: Edit directly on GitHub

1. Navigate to the page you want to edit
2. Click the "Edit this file" button (the pencil icon)
3. Make your changes and submit a pull request

### Option 2: Local development

1. Fork and clone this repository
2. Install the Mintlify CLI: `npm i -g mint`
3. Create a branch for your changes
4. Make changes
5. Run `mint dev` from `docs/guides/` and preview at `http://localhost:3000`
6. Run `mint broken-links` before opening a PR
7. Commit and submit a pull request

## Site structure

Each file path maps 1:1 to a URL. Pages not listed in `docs.json` are hidden: reachable by link, absent from the sidebar.

| Path | Contents |
|---|---|
| `<category>.mdx` | One guide per instrument category (`psu`, `dmm`, `scope`, ...). |
| `<category>/<Driver>.mdx` | Hidden page per vendor driver, linked from its category's card grid. |
| `snippets/drivers/` | Reusable driver cards and page bodies. Never built as pages. |
| `library/` | Conceptual and reference content. |
| `examples/` | Generated by `just gen-examples`. Don't edit by hand. |

Importing a page as a component (`import X from "/page.mdx"`) makes its own route 404. Keep reusable content in `snippets/`.

## Common tasks

### Add a driver to an existing category

1. Under `snippets/drivers/<category>/<driver-class-name>/`, add `image.png`, `card.mdx`, and `driver-page.mdx`. Copy an existing driver's shape.
2. Add `<category>/<DriverClassName>.mdx`, importing the card and driver page. Copy an existing driver's shape.
3. Add the card to the grid in `snippets/drivers/<category>.mdx`.
4. Add the driver to the Vendor Drivers table in `docs/sdk/instruments/<category>.md` (see [`docs/sdk/AGENTS.md`](https://github.com/nominal-io/instro/blob/main/docs/sdk/AGENTS.md#adding-a-vendor-driver)), link the driver page to its class page, and check with `just build-docs && just check-sdk-links`.
5. Run `mint broken-links`.

### Add a new instrument category

1. Add the category guide `<category>.mdx` and its driver snippets and pages.
2. Add the category to the Instruments group in `docs.json` and to `instruments.mdx`.
3. Add a section to `library/custom-instruments.mdx`, and to `library/config-files.mdx` if it accepts `config=`.
4. Add example scripts under `examples/<category>/`, run `just gen-examples`, and add `examples/<category>/index` to the "Contents" group of `docs.json`'s Examples tab. Also add a display name to `CATEGORY_TITLES` in `generate_examples.py` and a card to `examples.mdx`.
5. Add the category to the SDK site (`docs/sdk/instruments/<category>.md` and the Instruments toctree in `docs/sdk/index.md`).
6. Run `mint broken-links`, `mint validate`, and `mint export`.

### Examples

Example pages are generated from scripts in `examples/<category>/`, and from `<submodule>/examples/` inside `instro-unstable` and `instro-contrib`. Unstable and contrib examples share one index page per package, so they never need a `docs.json` edit. `just check-examples` runs in CI and fails if generated pages are stale or an index page is missing from the Examples tab.

## Terminology

- Call the library **`instro`**. Reserve *Nominal* for the platform (Nominal Core, Nominal Connect).
- Keep HAL class casing: `InstroPSU`, `InstroDMM`, `InstroDAQ`, and so on.
- A *channel* is a named signal for a series of values. Its glossary tooltip is `snippets/glossary/channel.mdx`.

## Writing guidelines

- Be concise and clear.
- Use active voice and the imperative: "Configure the check", not "You can configure the check".

- Use sentence case for headings, **bold** for UI elements, and `code` for files, commands, and identifiers.
- Link class and module references to the SDK docs.
- Document `instro` only. Link out for Nominal Core, Nominal Connect, and the dashboard.
